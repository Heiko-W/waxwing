# 036 — Twelve machine-translated languages, and the gate that makes them safe to ship

- **Status:** accepted
- **Date:** 2026-08-29
- **Work package:** issue #50 ("new language" — a Stalwart operator asking for Russian)
- **Relates to:** `docs/translating.md` (which this contradicts), `scripts/locale-rules.mjs`,
  `scripts/check-locales.mjs`, `apps/web/src/i18n/index.ts`, `apps/web/src/i18n/locales.test.ts`,
  `.weblate`

## Context

`docs/translating.md` opens by ruling out exactly what this ADR does:

> It deliberately does not describe a way to generate translations automatically: this is a mail
> client, and a reader who confuses *Discard* with *Archive* loses a message. A string nobody has
> read is not a translation.

That sentence is right about the risk and wrong about the alternative it implies. The pipeline it
describes — Weblate, a review queue, native speakers — had been in place and had produced no
language in the time it existed. The first person to ask for one asked whether they should fork the
project to get it, which is the outcome the pipeline was supposed to prevent.

So the choice was never "machine translation or a reviewed translation". It was "machine
translation, or English for everyone who does not read German".

Three options were weighed.

1. **Point the reporter at Weblate and wait.** Honest, and the status quo: it is what the repository
   already offered, and what produced nothing. It also puts the entire cost of the first language on
   the one volunteer least equipped to carry it — someone who has to learn the key layout, the
   plural suffixes and the placeholder rules before their first string.
2. **Ship Russian only**, since that is what was asked for. Rejected because almost all of the cost
   here is fixed: the plural machinery, the endonym picker, the checker, the docs. Paying it for one
   language and again for the next twelve is the expensive order.
3. **Ship twelve languages generated by a translating agent, behind a mechanical gate**, and make
   correction the cheap path rather than authorship.

## Decision

**Option 3.** `cs`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`, `ru`, `tr`, `uk` and `zh` join `en`
and `de`, generated per language against the English bundle and the German one (as a register
reference), each one iterated until `scripts/check-locales.mjs` passed.

**No automated check can tell whether a translation is good.** What the gate does instead is remove
the failure classes that are invisible to a reviewer and fatal at run time, so that what is left is
only ever a question of *wording* — which a speaker of the language can then fix in one line:

- **Key parity**, with plural variants collapsed, in both directions. A missing key renders as its
  own dotted path on screen.
- **Plural forms**, taken from `Intl.PluralRules` rather than a table. Russian, Ukrainian, Polish and
  Czech select four categories where English selects two; a bundle missing `_few` falls back to
  English *mid-sentence* for exactly the counts 2–4.
- **Placeholders.** An invented `{{…}}` has nothing to interpolate and renders as literal braces.
  Dropping one is allowed (a singular sentence rarely needs to repeat the number) — except
  `{{product}}`, which may never be dropped and whose expansion may never be written out, or a
  hoster's rebranding (FR-DEP-04) is defeated by a translation.
- **Typography**, one spelling per mark across every language: `’` not `'`, `…` not `...`.
- **A copy of the source.** More than half the values byte-identical to English is not a translation;
  it is the file having been duplicated.

The rules live in `scripts/locale-rules.mjs` and are run from two places — `pnpm test` (the gate) and
`node scripts/check-locales.mjs <lang>` (the pre-flight a translator runs in a loop, one language at
a time). One implementation, because a rule only the CLI knew would not block a release, and a rule
only the gate knew would ambush the translator at the end.

**`docs/translating.md` is rewritten**, not quietly left standing: it now says these twelve bundles
are machine-generated and unreviewed, and that correcting one is a one-line pull request.

### Two changes that follow from the count, not from the method

- **The picker shows endonyms.** It used to translate the names (`t('language.de')`), which works
  until the list is longer than two: fourteen languages naming fourteen languages is 196 strings, and
  a reader who has landed in the wrong language is looking for their own — spelled the way *they*
  spell it. `languageName()` asks `Intl.DisplayNames`, following the argument
  `settings/stalwart-model.ts` already makes for `languageLabel`. The `language.en`, `language.de`
  and `language.short.*` keys are deleted; `language.short` had no reader in the source at all.
- **`SUPPORTED_LANGUAGES` is alphabetical by tag** and `DEFAULT_LANGUAGE` is exported, because two
  gates had been reading the source language off `SUPPORTED_LANGUAGES[0]` — correct only while that
  array happened to start with `en`.

## Consequences

- **A Russian, Czech or Japanese reader gets Waxwing in their language today**, and every string
  they read is one a native speaker can improve without first learning the repository.
- **The service worker precache grows from 478 KB to 769 KB gzipped** (measured: 334 KB of that is
  the fourteen locale chunks, up from 45 KB). Twelve of the fourteen locale
  chunks are dead weight for any given reader, and they are precached anyway: the shipped contract
  (`scripts/check-dist-contract.mjs`) is that the precache is *exactly* `index.html` plus every
  emitted asset, and that contract exists to catch a glob that silently stops matching. Weakening it
  to exclude locales would trade a real gate for a one-time download. **No budget is broken** —
  NFR-PERF-01's 300 KB is initial JS, and locale bundles have always been lazy and excluded
  (`.size-limit.js`); the measured figure is **283.94 KB gz of 300**, and all fourteen chunks are
  still named `common-*.js`, so the existing exclusion covers them without an edit. If the install size ever needs to come down, that is its own change, with its
  own answer for how an offline reader gets a language they have never opened.
- **Quality is unwarranted and said so out loud.** These are not reviewed translations and
  `docs/translating.md`, the README and issue #50 all say so. The expected failure is an awkward or
  over-literal phrase, not a wrong destructive verb — those were translated against an explicit
  instruction that *Delete forever* may never read softer than the English.
- **RTL is still untested.** `RTL_LANGUAGES` continues to list eight scripts and none of them ships;
  Arabic and Hebrew were deliberately left out of this batch, because a first right-to-left bundle
  would put a layout direction nobody has ever seen in front of readers. It remains one bundle away.
- **The next language is cheap**: a file, a tag, `pnpm verify`.
